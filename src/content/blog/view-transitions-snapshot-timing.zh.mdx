我花了一个下午给博客加 View Transitions。淡入淡出在跑，页面也切换了。但每次转场都有一丝旧内容的残影，在新页面出现前短暂闪烁。这个 bug 足够微妙，差点直接发布了。

## 工作原理

两个阶段：

1. **捕获**——浏览器截取当前页面快照，然后执行回调。
2. **动画**——回调的 Promise resolve 时，浏览器截取新页面快照，在两张快照之间插值。

关键细节：浏览器在 Promise resolve 的那一刻截取"新页面"快照。如果那时候 DOM 还没更新，"新"快照截到的仍然是旧页面。

```typescript
document.startViewTransition(async () => {
  // 浏览器在这里截取旧页面
  await doYourNavigation();
  // 浏览器在这里截取新页面
  // 此时 DOM 必须已经反映新内容
});
```

## Bug 在哪

```typescript
// ❌ 在新路由 commit 之前就 resolve 了
document.startViewTransition(async () => {
  await router.push(href);
  // router.push() 调度导航之后立即返回。
  // DOM 还在显示旧页面。
});
```

Next.js App Router 的 `router.push()` 不等新组件树 mount。它调度导航然后返回。Promise 在旧页面还在屏幕上时就 resolve 了，浏览器把旧内容截成了"新"帧。

动画变成两帧相同内容的交叉淡入。页面在闪烁，不是在转场。

一个 `console.log` 就确认了：

```typescript
document.startViewTransition(async () => {
  await router.push(href);
  console.log(document.title);  // 还是旧标题
  console.log(window.location.pathname);  // 还是旧路径
});
```

## 修复：模块级 Resolver

把"发起导航"和"路由就绪"分开。React 的 `useEffect` 以 `pathname` 为依赖，在新页面 mount 后——DOM commit 之后——才触发。

```typescript
let pendingResolve: (() => void) | null = null;

function resolvePending() {
  if (pendingResolve) {
    pendingResolve();
    pendingResolve = null;
  }
}

export function TransitionLink({ href, children, ...props }: TransitionLinkProps) {
  const router = useRouter();
  const pathname = usePathname();

  useEffect(() => {
    resolvePending();
  }, [pathname]);

  const handleClick = (e: React.MouseEvent<HTMLAnchorElement>) => {
    if (!('startViewTransition' in document)) return;
    e.preventDefault();
    resolvePending();

    const transition = document.startViewTransition(
      () =>
        new Promise<void>((resolve) => {
          pendingResolve = resolve;
          router.push(href);
        })
    );

    const timeout = window.setTimeout(() => {
      transition.skipTransition();
      resolvePending();
    }, 600);

    transition.finished
      .finally(() => window.clearTimeout(timeout))
      .catch(() => {});
  };

  return <Link href={href} onClick={handleClick} {...props}>{children}</Link>;
}
```

Promise 一直挂起，直到新页面的 `useEffect` 触发。因为 `useEffect` 在 DOM commit 之后才运行，浏览器截到的新页面快照是真实的新内容。

## 为什么用模块级变量

转场完成后，旧页面的组件实例已经消失。新页面的 `TransitionLink` mount 了，它的 `useEffect` 触发。它需要找到旧页面 click handler 设置的 resolver。

`useRef` 会跟旧组件一起消亡。模块级变量在同一个页面生命周期内跨 mount 持久存在。新的 `useEffect` 找到 `pendingResolve`，调用它，转场干净地完成。

## 600ms 安全阀

慢网络或重型页面可能让导航卡住。没有兜底的话，View Transition 会把页面冻结在动画中间。

`transition.skipTransition()` 放弃动画，立即显示新页面。`resolvePending()` 解开挂起的 Promise。超时触发，页面继续走，`transition.finished` handler 清理计时器。

## 边界情况

**修饰键。** `⌘Click`、`Ctrl+Click`、`Shift+Click` 应该打开新标签页。检测到修饰键时提前退出。

**同路由导航。** 点击当前页面的链接不该触发转场，只需要滚回顶部。

**减弱动效。** `prefers-reduced-motion: reduce` 完全禁用动画，透传到默认导航。

**不支持的浏览器。** 能力检测（`'startViewTransition' in document`）是运行时依据。查 [MDN 的兼容性数据](https://developer.mozilla.org/en-US/docs/Web/API/View_Transition_API#browser_compatibility)了解当前矩阵。

## 留下来的认知

契约很严格：`router.push()` 代表导航已启动，不代表新 DOM 已就绪。"已启动"和"已就绪"之间的间隙就是 View Transitions 崩掉的地方。修复不复杂，但 bug 足够隐蔽，会在没人注意的情况下发到生产——页面"能用"，只是在闪烁而不是在转场。

生产组件还处理了仅 query 变化、键盘导航和主题转场的 `view-transition-name`。这些检查应保留在真实实现里，本文只覆盖核心时序问题。
