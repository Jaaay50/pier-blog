我做了一个实验室页面，放了六个交互 demo。Navier-Stokes 流体模拟。粒子系统。Shader 调色台。Verlet 物理。Curl-noise 流场。参数曲面变形。全部零依赖——没有 Three.js，没有 p5.js，没有任何处理框架。

技术上跑通了。更难的问题是：一个作品集到底需要多少视觉复杂度？

## 为什么零依赖

Three.js 压缩后 600KB。对一个每个 demo 都是独立 canvas 的实验室页面来说，为了便利付出的代价太重了。

我想让每个 demo 证明的是我理解底层数学，而不是我会配置一个库。原始 WebGL 调用写的粒子系统，真实 Navier-Stokes 方程写的流体模拟，手写 Verlet 积分和空间哈希的物理沙盒。

代价：什么都要更久，有些东西——比如像样的轨道控制或 GLTF 加载器——不值得手写。对展示页面上的独立 demo 来说，数学优先的方式说得通。对生产级 3D 应用，我会毫不犹豫地用 Three.js。

## 流体模拟

旗舰 demo。WebGL2，Navier-Stokes，ping-pong 帧缓冲，涡量约束，每帧 20 次 Jacobi 压力迭代。

实现顺序比我预想的重要：

1. 先让单通道对流跑起来。只是让染料动。
2. 加入速度场。染料开始跟着场走。
3. 加压力投影。没有它，流体会压缩而不是流动。
4. 加涡量约束。没有它，模拟衰减太快——漩涡死得太早。
5. 加用户输入。拖拽注入染料和速度。

每一步都可以单独测试。第三步是 debug 花的时间最长的地方——压力求解器需要足够的迭代次数才能收敛，迭代不够会产生视觉伪影，看起来像是对流出了问题，实际上是压力场不对。

最难的 bug：某些 GPU 上黑屏。原因是顶点着色器里缺 `layout(location=0)`。有些驱动默认把属性位置设为 0，有些不设。加上显式的 layout qualifier 之后在所有测试硬件上都正常了。

```glsl
// ❌ 在部分 GPU 上能跑，在其他上黑屏
in vec2 aPosition;

// ✅ 显式 location——可移植
layout(location=0) in vec2 aPosition;
```

## 粒子标题

首页 Hero 用了一个粒子系统，从碎裂状态重新聚合成页面标题。管线：

1. 等 `document.fonts.ready`
2. 在离屏 Canvas 2D 上渲染标题文字
3. 用 `getImageData` 从渲染结果里采样像素位置
4. 在随机位置创建 WebGL 粒子，然后 morph 到采样位置

采样步骤在衬线字体上有精度问题。文字用 `textBaseline = 'top'` 渲染的，但衬线的上升部分把墨水推到了预期范围之上。改成 `textBaseline = 'middle'` 并调整垂直偏移之后修好了——粒子位置现在跟渲染出的字形匹配，不依赖字体度量。

降级路径：如果 WebGL 不可用、设备性能低或 `prefers-reduced-motion` 开启，标题回退到 CSS 逐字上浮动效。文字始终在 HTML 里，SEO 不受影响。粒子只是上面的一层。

## 知道什么时候该停

实验室页面做完之后，我在首页加了动态背景。暗色模式下的 Galaxy 星空，亮色模式下的 Aurora 光波。两个都开满透明度。页面看起来像屏保。

一次外部设计审查指出了问题：五个同时运行的动画元素在争夺注意力。用户不知道该看哪里。粒子标题——真正的展示品——淹没在噪声里了。

修复是降低透明度。Galaxy 从 0.45 降到 0.22。Aurora 从 0.40 降到 0.18。技能卡加了 hover 门控——默认只有一张卡的动画在跑，其他的在交互时才激活。

结果：粒子标题现在是清晰的视觉焦点。背景仍然存在，但不再争抢。有一个 demo 被整个移除了——一个波浪网格分隔带，它跟 Shader 调色台的视觉语言重复了。

这是更难的一课。搭建令人印象深刻的 demo 是一个可解的工程问题。决定同时展示多少个是一个设计判断，而我的直觉是错的。更多的视觉复杂度让页面更差了，不是更好。

## 让我真正满意的工程

不是 shader。是降级路径。

每个 demo 在挂载前检查 WebGL 能力。每个动画检查 `prefers-reduced-motion`。每个 canvas 用 `next/dynamic` 避免 SSR。每个交互元素都有静态回退——一张截图、一个简化的 CSS 版本、或者只有文字内容不带视觉层。

实验室页面在 4G 节流且 WebGL 禁用的情况下不到 2 秒加载完。六个 demo 全部显示有意义的静态内容。页面在没有 JavaScript 的情况下可用。

这些工作不会出现在 demo reel 里，但它是让一个技术演示和一个生产页面之间产生区别的工作。
