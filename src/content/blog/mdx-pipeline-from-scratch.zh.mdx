我不是一开始就选了 MDX。一开始选的是 headless CMS，花了两天跟它的富文本转 React 管线搏斗，然后决定自己拥有内容层比依赖一个可能改 schema 的 API 更靠谱。

最终的 MDX 管线大约 150 行代码。让它正确运行花的时间比让它能跑花的时间更长。

## 为什么不用 CMS

CMS 给了我所见即所得编辑器、图片托管和内容 API。它没给我的：

- **用 Shiki 做语法高亮。** CMS 把代码块渲染成带行内样式的 `<pre>`。我想要能控制主题的正确 tokenization。
- **在内容里嵌入自定义组件。** 我需要 `<Callout>`、`<CodeBlockWrapper>` 和嵌在文章里的交互 demo。富文本不支持任意 React 组件。
- **Git 历史。** 我想看到一篇文章最后一次改动的时间、谁改的、diff 内容。CMS 数据库不给我这些。
- **离线编辑。** 我在编辑器里写作，不是在浏览器标签页里。

MDX 全部满足。代价：构建管线、渲染和每一个边界情况都是我自己的事。

## 管线

内容住在 `src/content/blog/`，是 `.mdx` 文件。每篇文章有英文和中文版本：`article-slug.en.mdx` 和 `article-slug.zh.mdx`。

### 第一步：读取并解析 frontmatter

```typescript
import rawMatter from 'gray-matter';
import { load as yamlLoad } from 'js-yaml';

function matter(input: string) {
  return rawMatter(input, {
    engines: {
      yaml: (s: string) => yamlLoad(s) as object,
    },
  });
}
```

自定义 YAML engine 的存在是因为 `gray-matter` 内部用的是 `js-yaml@3` 的 `safeLoad`，这个 API 在 `js-yaml@4` 里被移除了。项目出于安全原因固定了 `js-yaml@^4`，所以默认 engine 会抛错。这种东西在依赖升级之前一直没问题，然后在构建时无声地崩掉。

### 第二步：计算元数据

```typescript
function calcReadMinutes(content: string): number {
  const cjk = (content.match(/[\u4e00-\u9fff\u3040-\u309f\u30a0-\u30ff]/g) || []).length;
  const ascii = content.replace(/[\u4e00-\u9fff\u3040-\u309f\u30a0-\u30ff]/g, ' ');
  const words = ascii.trim().split(/\s+/).filter(Boolean).length;
  return Math.max(1, Math.ceil(cjk / 300 + words / 200));
}
```

中文的阅读速度跟英文不一样——大约每分钟 300 字对 200 词。双语博客需要两种计算，否则一半内容的预估时间是错的。

### 第三步：用 rehype 插件渲染 MDX

MDX 编译链：

```typescript
import { compile } from '@mdx-js/mdx';
import rehypePrettyCode from 'rehype-pretty-code';
import rehypeSlug from 'rehype-slug';

const compiled = await compile(content, {
  remarkPlugins: [remarkInjectLineNumbers],
  rehypePlugins: [
    rehypeSlug,
    [rehypePrettyCode, {
      theme: { dark: 'one-dark-pro', light: 'github-light' },
      defaultLang: 'typescript',
    }],
  ],
});
```

`rehype-pretty-code` 底下用的是 Shiki。它在构建时 tokenize 代码块，输出带行内样式的 `<span>` 元素——语法高亮不需要客户端 JavaScript。双主题配置为亮色和暗色模式各生成一套样式，通过 CSS class 切换。

`rehypeSlug` 给标题加 `id` 属性，粘性目录用它做 scroll-spy。

### 第四步：自定义组件

MDX 允许把 HTML 元素映射到 React 组件：

```typescript
const components = {
  pre: CodeBlockWrapper,  // 加复制按钮和 hover 效果
  a: SmartLink,          // 外链加 target="_blank" 和 rel="noopener"
  img: OptimizedImage,   // 用 Next.js Image 包裹，带 blur 占位
};
```

`CodeBlockWrapper` 是一个客户端组件，包裹 Shiki 静态渲染出来的 `<pre>`。语法高亮已经在 HTML 里了；wrapper 加的是复制到剪贴板按钮、标题栏和 hover 效果。代码本身的显示完全不需要 JavaScript。

## 边界情况

**行号。** `rehype-pretty-code` 支持行号，但我需要它默认对所有代码块开启，而不是在每个代码围栏上手动加 `showLineNumbers`。一个自定义 remark 插件（`remarkInjectLineNumbers`）在 rehype 处理之前把 meta 属性注入 AST。

**CJK 行高。** 中文需要比英文更大的行高。`prose` class 处理拉丁文本没问题，但 CJK 字符在同样的行高下会被裁切。修复方法是用 `html[lang="zh"]` 限定的样式，稍微增大 `line-height` 和 `letter-spacing`。

**Frontmatter 校验。** MDX 文件就是文件。没有 schema 强制——`date` 字段缺了的话，页面会渲染成 `"1970-01-01"` 而不是在构建时报错。我加了一个测试，用管线加载每一篇文章并检查必填字段是否存在且格式有效。这在 `npm test` 阶段就能抓住错误，而不是在生产环境。

**gray-matter 与日期。** 如果在 YAML frontmatter 里写 `date: 2026-03-10` 不加引号，`js-yaml` 会把它解析成 JavaScript `Date` 对象而不是字符串。`toPost` 函数会把它转回字符串，但如果不注意，时区偏移可能让显示的日期偏移一天。frontmatter 里的日期永远加引号：`date: "2026-03-10"`。

## 如果重来我会改什么

管线能用。它很快（12 篇文章的构建时间不到 2 秒），类型安全（`BlogPost` 接口强制形状），可测试（每篇文章走同一条代码路径）。

我会改的：双文件命名约定（`slug.en.mdx` / `slug.zh.mdx`）意味着每个 slug 解析函数都要先剥掉 locale 后缀再去重。按目录组织（`slug/en.mdx`、`slug/zh.mdx`）更干净，但当前约定已经接进了构建管线、sitemap 生成器、RSS feed、OG 图生成器和重定向配置。迁移成本超过了烦恼。

有时候正确的架构就是你能发出去的那个。
